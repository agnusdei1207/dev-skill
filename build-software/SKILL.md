# 소프트웨어 개발 방법론

철학, 사람의 두 질문, 다섯 축 게이트, 위상 모델, 공통 핑계는 [방법론 정본](references/methodology.md)에 있다. 이 파일은 어느 정본을 언제 여는지와 작업 유형별 경로만 정한다. 개발 작업에서 쓰는 모든 글(README, `docs/`, 보고, 커밋 메시지, PR 설명)은 저장소 공통 스킬 `write-readable-text`를 따르고, 바꾼 md의 서식 검사가 0건이어야 완료다.

## 참조 문서 읽는 법

주제별 참조 문서는 같은 골격이다: 첫 단락(소유 범위) → 절차(순서가 있는 작업일 때) → 판단 기준 → 핑계와 반박 → 위험 신호 → 종료 게이트. 방법론 정본은 공통 핑계만, 완료 체크리스트는 게이트 자체만 가지며, 교차 품질은 절마다 `실패로 본다`가 위험 신호다.

- 핑계와 반박: 왼쪽 문장이 머릿속에 떠오르면 그 단계를 건너뛰려는 신호다. 오른쪽대로 돌아간다.
- 위험 신호: 산출물에서 하나라도 보이면 멈추고 해당 절로 돌아간다.
- 종료 게이트: 적용되는 항목이 전부 증거로 체크돼야 다음 위상으로 간다.

## 컨텍스트 로딩

한 번에 다 읽지 않는다. 시작 시 이 파일과 [방법론 정본](references/methodology.md)·[인텐트](references/intent.md)만 읽는다. 위상에 들어갈 때 그 위상의 정본을, 판정이 갈릴 때만 세부 정본을 연다. 그 뒤로는 [완료 체크리스트](references/completion-checklist.md)의 위험도별 경로로 일한다. 대상 저장소에서 먼저 읽을 문서는 [유지보수](references/maintenance-and-brownfield.md)의 진입 절차를 따르고, 코드는 반경 안만 읽는다. 워커에게는 그 태스크의 범위·인터페이스·검증·해당 정본만 넘긴다.

## 저장소 계약 우선

운영 사항(빌드·게이트 실행 방식, 커밋 규약, 보호 구간, 리소스 상한, 구조 규칙)은 대상 저장소의 `AGENTS.md`/`CLAUDE.md`가, 목적·장기 제약·영구 결정은 프로젝트 인텐트가 정본이다. 충돌 시 우선순위와 승인 경계는 방법론 정본 8절에 있다. 이 방법론을 대상 저장소에 복제·요약하지 않는다. 특정 저장소의 스크립트·도구 이름·사고 사례는 그 저장소의 운영 계약에 두고 이 방법론에는 일반화한 원칙만 남긴다.

## 작업 유형별 경로

- 기존 프로젝트 투입·유지보수(대부분): 유지보수 정본의 진입 절차를 먼저 밟는다.
- 신규 기능: 인텐트 → 사양·계획 → (닿으면) UX/UI → TDD → 플럼빙 → QA. 새 개념이 생기면 도메인 모델링, 새 파일 자리는 코드 조직. 자율 실행이면 루프 운영.
- 도메인 모델링: 용어가 흔들리거나 규칙이 여러 곳에 흩어졌거나 새 도메인을 시작할 때. 도메인 모델링 정본의 적용 강도를 먼저 판정하고 세션 절차로 용어집·컨텍스트 맵·불변식 소유자를 정한 뒤, 코드 이동은 리팩터 경로로.
- 구조 정리(폴더·파일·모듈 경계): 코드 조직 정본의 구조 감사로 후보를 열거 → 리팩터 경로(특성화 테스트 → 순수 이동 증분 → 플럼빙 → QA) → 구조 지도 갱신. 이름 변경은 별도 증분.
- 리팩터(동작 보존): 리팩터링·코드 품질 → 특성화 테스트 → 플럼빙 → QA. 동작 변경은 별도 인텐트.
- 버그픽스·장애: 진단과 디버깅으로 원인을 관측 확정 → TDD 정본의 근본 원인 수정. 사용자가 설명·질문 중이면 진단만 보고한다.
- 신규 프로젝트: 유지보수 정본의 부트스트랩.
- UX/UI: UX/UI 정본 필수. UI를 만들면 컴포넌트와 재사용 정본의 공유 컴포넌트·토큰.
- 성능: 교차 품질 정본의 성능 절.
- 교차 게이트(해당할 때만): 신뢰 경계·외부 의존·스키마·의존성·새 도구·배포·hot 경로·설정·시스템 언어·정책을 건드리면 교차 품질 정본의 해당 절.

## 실행 절차

1. 저장소 계약·프로젝트 인텐트를 읽고 위험도·가역성을 판정한다(사양·계획 정본).
2. 작업 인텐트를 확인한다. 없거나 비면 초안을 세워 승인받는다. 인터뷰 조건은 인텐트 정본에 있다.
3. 수용 기준을 작은 증분으로 쪼개고 각 증분을 루프 운영 정본의 PDCA로 돌린다. 위상마다 해당 정본의 종료 게이트를 통과해야 다음으로 간다.
4. 매 GREEN 뒤와 인텐트 완료 직전에 리팩터링 정본의 케이던스를 밟는다.
5. 인텐트의 AI 판정 절과 구조 지도를 코드와 같은 변경에서 갱신하고, 보고 정본의 골격으로 압축 보고한다. 커밋·푸시는 방법론 정본 8절의 승인 범위 안에서만 한다.
6. 프로젝트 인텐트가 정한 케이던스마다 주기 아키텍처 리뷰를 돌린다.

완료 판정은 [완료 체크리스트](references/completion-checklist.md)에 있다.
