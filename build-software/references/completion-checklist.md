# 완료 체크리스트

이 파일이 완료 정의를 소유한다. 완료는 모든 수용 기준이 증거로 통과하고, 저장소 게이트가 실측 green이며, 품질 불변식이 유지되고, docs(AI 판정·구조 지도)가 코드와 같은 변경에서 갱신됐을 때 성립한다. 각 조건은 이진 판정으로 결정한다. 통과에는 실행·대조 증거, 실패에는 관측 결함, 미검증에는 실행하지 못한 이유, N/A에는 비해당 근거를 붙인다. 실패·미검증은 이유를 설명해도 통과가 아니다. 점수는 [루프 운영](loop-operation.md)의 보조 지표다.

## 위험도별 사용법

위험도와 가역성 판정은 [사양·계획](spec-and-plan.md)에 있다. 이 파일은 판정된 위험도마다 쓰는 점검표만 정한다.

| 위험도 | 사용하는 점검표 |
|---|---|
| LOW | 공통 6항목 + 실제 해당 조건 행. 별도 원장·전체 정본 완독 불필요 |
| MED | 공통 6항목 + 해당 조건 행, 태스크·실패 경로·증거 표 |
| HIGH | 공통 6항목 + 해당 조건 행, 단계 적용·복구 실측·필요한 결정 기록 |

저장소 지정 필수 게이트를 경량 경로로 면제하지 않는다.

## 공통 6항목

- [ ] 성공 기준·범위·위험도·보호 구간 확인, 기존 승인 범위에서 진행. 기존 인텐트·ADR·용어집 보존 및 필요한 기록 연결([인텐트](intent.md)).
- [ ] 수용 기준별 실행·대조 증거 확보. 동작 변경은 실제 RED→GREEN, 리팩터는 특성화 테스트, 문서 변경은 링크·명령·시나리오 대조([TDD](tdd-and-implementation.md)).
- [ ] 생산자→소비자→종료 경로 영향 확인, 해당 테스트·계약·설정·문서 동기화([플럼빙](plumbing-and-consistency.md)).
- [ ] 코드 변경 시 [품질 불변식](refactoring-and-code-quality.md)의 해당 항목 검증. 무관한 정리·조기 추상화·임시 산출물·비밀 노출 없음.
- [ ] 저장소 지정 검증 실측. 미실행·실패를 통과로 보고하지 않음. 무관한 실패는 범위 확대 없이 기록([QA](qa-and-verification.md)).
- [ ] 인텐트 판정·필요한 구조 지도·남은 위험 갱신, 완료와 미완료 분리 보고. 커밋·푸시·배포는 사용자 승인 범위에서 수행([보고](reporting.md)).

## 판정 예시

한 파일의 빈 입력 처리 수정은 영향이 국소적이면 공통 6항목과 결함 행을 사용한다. 실패 테스트·최소 수정·회귀·저장소 지정 게이트로 판정하며 화면·배포 변경이 없으면 그 행을 작성하지 않는다. 공유 입력 계약을 바꾸면 MED로 올리고 모든 소비자 계약을 검증한다.

같은 근거에는 같은 통과·실패·미검증 결과가 나와야 한다. 이미 통과한 범위를 점수나 수정 흔적을 만들기 위해 바꾸지 않는다.
