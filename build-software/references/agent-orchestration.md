# 상위·하위 에이전트 루프

이 파일은 상위 에이전트(계획·검증)와 하위 에이전트(구현)의 분업, 지시서 계약, 합격할 때까지의 무한 반복, 판정과 기록을 소유한다. 사용자가 "최종 합격·완료까지 반복"을 지시하면 이 루프는 증거 기반 합격 판정이 나올 때까지 끝나지 않는다. 증분·PDCA·채점·커밋 케이던스는 [루프 운영](loop-operation.md)이 소유하고, 여기서는 역할과 반복 종료 조건만 얹는다.

## 역할

| 역할 | 담당 | 하지 않는 일 |
|---|---|---|
| 상위(계획·검증) | 목표·완료 기준 확정, 지시서 작성, 하위 모델 호출, 게이트 직접 실측, 요구사항·기준 화면 대조, 판정, 인텐트 갱신, 커밋·푸시 | 대량 구현(검증에 필요한 최소 수정은 예외) |
| 하위(구현) | 지시서 범위의 코드 수정, 테스트 추가, 게이트 실행, 증거를 붙인 보고 | 완료 판정, 범위 밖 수정, 판단이 필요한 결정 |

- 하위 구현은 별도의 하위 모델을 호출해 실행한다. 상위 모델은 그 결과를 검증하고 직접 대량 구현하지 않는다.
- 호출 방식과 모델 이름은 사용자 지시나 대상 저장소 운영 계약을 따른다. 지정이 없으면 상위가 임의로 바꾸지 않는다. 서브에이전트 위임과 원샷 실행을 모두 쓸 수 있지만, 어느 쪽이든 결과는 상위가 직접 실측한다.
- 독립 리뷰는 가능하면 서브에이전트에 맡긴다. 서브에이전트를 쓸 수 없으면 [루프 운영](loop-operation.md)의 리뷰 절차로 상위가 다른 반증 시나리오·체크리스트로 대체하고 그 사실을 기록한다. 리뷰 자체를 생략하지 않는다.
- 하위 보고의 "완료"는 가설이다. 실행 로그·수치가 없으면 완료로 받지 않는다([루프 운영](loop-operation.md)의 병렬 실행과 위임 경계).

## 지시서 계약

지시서를 매 반복 새로 쓰지 말고, 실패한 지점만 바꿔 같은 하위에 되먹인다.

1. 목표: 계획서의 한 단계 또는 한 화면 묶음. 완료 기준을 계획서에서 그대로 옮긴다.
2. 현재 상태: 변경 파일, 미완료 지점, 이전 반복의 실패·미검증 항목.
3. 범위: 맡은 파일과 인터페이스, 비범위, 보호 구간, 금지 사항.
4. 게이트: 대상 저장소 운영 계약이 정한 검증 명령을 그대로 적는다.
5. 보고 형식: 변경 파일, 실행 명령, 통과 수와 출력, 남은 결함, 판단이 필요한 지점. 로그와 수치 없는 완료 보고를 금지한다.

## 무한 반복

```text
반복:
  상위: 계획서에서 한 목표와 완료 기준을 고른다
  상위: 현재 상태·금지 사항·게이트·보고 형식을 넣어 지시서를 쓴다
  상위: 하위 모델을 호출해 지시서를 실행시킨다
  하위: 지시서 범위만 구현하고 게이트를 돌려 증거를 보고한다
  상위: 게이트를 직접 실측하고 완료 기준과 대조한다
  통과 && 완료 기준 충족:
    증거를 기록하고 커밋·푸시한 뒤 다음 목표로 간다
  아니오:
    실패·미검증과 구체적 수정 지시를 같은 하위에 되먹인다
```

- 반복 횟수를 상한으로 삼아 멈추지 않는다. [루프 운영](loop-operation.md)의 fix round 기본값은 사용자가 완료까지 반복을 지시하지 않은 작업에 적용된다. 합격·완료까지 반복하라는 지시가 있으면 종료 조건은 상한이 아니라 합격 판정이 된다.
- 매 반복은 독립 증분이다. 실패한 반복의 변경을 근본 원인 확인 없이 다음 반복에 쌓지 않는다. 같은 실패가 되풀이되면 지시서와 가정을 다시 검토한다.
- 통과한 증분마다 커밋·푸시하고 다음 목표로 간다. 단계 하나가 끝났다고 인텐트 전체를 완료로 바꾸지 않는다.
- 멈춤 사유는 합격 판정, 사람의 승인이 필요한 행위, 증거를 만들 수 없는 게이트뿐이다. 게이트를 실행할 수 없으면 완료가 아니라 블로커로 보고한다. 합격 판정을 흉내 내어 루프를 끝내지 않는다.

## 합격 판정

- [완료 체크리스트](completion-checklist.md)의 이진 판정, 저장소 게이트 실측, 완료 기준 대조가 모두 통과해야 합격이다.
- 상위가 보기에 요구사항이나 기준 화면과 구조가 다르면(메뉴, 탭, 패널 비율, 표 밀도 등) 그것도 실패다. 차이를 수용 기준으로 적어 하위에 되먹인다.
- 하위의 자기 보고와 자기 채점은 합격 증거가 아니다. 상위가 실행 출력을 직접 확인한다.
- 인텐트의 체크박스는 실행 증거가 있는 항목만 `[x]`로 바꾼다. 나머지는 미검증으로 남긴다.
- 합격한 목표의 판정·증거·커밋 해시·남은 위험을 인텐트의 AI 판정 절에 기록한다.

## 핑계와 반박

| 핑계 | 반박 |
|---|---|
| "fix round를 넘겼으니 멈춘다" | 그 상한은 기본값이다. 사용자가 합격까지 반복을 지시했다면 종료 조건은 증거 기반 합격 판정이다 |
| "하위가 완료라고 보고했다" | 보고는 가설이다. 상위가 게이트를 실측하고 완료 기준과 대조하기 전에는 미검증이다 |
| "한 번 더 검증하면 비용이 든다" | 비용 때문에 증거를 생략하면 미완성을 완료로 보고하게 된다 |
| "게이트가 깨졌지만 다음 단계로 간다" | 실패·미검증은 합격이 아니다. 실패부터 되먹여 같은 하위에 다시 맡긴다 |
| "완료 지시가 있으니 배포도 진행한다" | 완료까지 반복하라는 지시는 배포·릴리스 승인을 포함하지 않는다([방법론](methodology.md) 8절) |

## 위험 신호

- 하위 보고만으로 합격을 선언하거나, 증거 없이 인텐트 체크박스를 `[x]`로 바꾸기
- 같은 실패가 담긴 지시서를 수정 없이 반복해서 보내기
- 상위가 게이트를 실행하지 않고 하위 출력만 인용하기
- 반복 횟수·시간을 이유로 미검증 항목을 남긴 채 완료 보고하기
- 단계 하나의 통과를 인텐트 전체 완료로 표시하기

## 종료 게이트

- [ ] 각 반복의 지시서에 목표·완료 기준·현재 상태·범위·게이트·보고 형식이 있었다
- [ ] 하위 모델을 호출했고, 상위가 게이트를 직접 실측해 완료 기준과 대조했다
- [ ] 실패·미검증은 구체적 수정 지시로 같은 하위에 되먹였다
- [ ] 독립 리뷰를 서브에이전트에 맡기거나, 부재 시 대체 리뷰를 수행·기록했다
- [ ] 합격 판정은 증거 기반 이진 판정이었고, 인텐트 AI 판정에는 실행 증거만 기록했다
- [ ] 합격한 증분은 커밋·푸시했고, 미완료 항목은 완료로 표시하지 않았다
