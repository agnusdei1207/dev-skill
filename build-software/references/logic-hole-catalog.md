# 논리 구멍 카탈로그 (Logic Hole Catalog)

작아서 넘어가는 가정이 논리 구멍이 된다. 이 파일은 코드·이름·타입·계약에 반복해서 숨어드는 사소한 가정의 목록을 소유한다. 각 항목은 `가정 → 깨지는 조건 → 확인 방법`이다. 사소함은 면제 사유가 아니다 — 판단 기준은 크기가 아니라 파급이며, 한 줄의 이름이나 비교 연산자 하나가 시그니처·저장·화면·테스트 전체에 잘못된 가정을 심는다. 위상 1(계획)과 위상 4~5(정합·검증)에서 이 목록을 실제로 훑고, 해당하는 항목은 테스트로 고정한다.

## 수량 (하나 vs 여럿)

- "하나뿐이다" → 수신자(브로드캐스트·멀티캐스트), 소유자, 세션·기기, 테넌트, 결과, 오류, 첨부가 여럿이거나 0개가 된다 → 이름·타입·컬럼·필드의 수가 0..1/1/0..N/1..N 중 실제 범위와 일치하는가. 단수 이름의 집합, 단일 슬롯 버퍼, 첫·마지막 원소만 처리하는 경로가 없는가(식별자·문구·주석 정본의 식별자 절).
- "비어 있지 않다" → 빈 목록·빈 문자열·0건 결과 → 빈 집합에서 반복문·집계·첫 원소 접근·UI 문구가 어떻게 되는가. 빈 배열에 대한 `all()`류 검사는 항상 참이다.
- "한 번만 호출된다" → 재시도·중복 클릭·재전송·재시작으로 여러 번 → 멱등한가, 두 번째 호출이 중복 부작용을 내지 않는가.

## 경계·범위

- 포함/배제 → 범위 끝(`<` vs `<=`), 페이지 마지막, 슬라이스 끝, 만료 시각 정각 → off-by-one 케이스를 경계값 양쪽에서 테스트한다.
- 0·음수·최대값 → 0으로 나눔, 음수 인덱스·수량, 정수 오버플로, 최대 길이 초과 → 경계 입력에서 거부·포화 동작이 정의됐는가.
- 인덱스 기준 → 0-based와 1-based 혼용(페이지 번호·행 번호·사용자 표시) → 경계에서 변환이 한 곳에서만 일어나는가.

## 시간

- "서버와 사용자의 시각이 같다" → 타임존, DST 전환, 로케일 → 저장은 타임존 포함, 표시는 로케일 변환. 날짜만 필요한 값(생일·마감일)을 시각으로 저장해 하루가 밀리지 않는가.
- "시간은 단조 증가한다" → 벽시계 조정·NTP 보정·재시작 → 경과 시간 측정·타임아웃·순서 판정은 단조 시계로, 기록은 벽시계로.
- "달·해는 규칙적이다" → 월말(31일+1개월), 윤년, 주 시작 요일 → 날짜 연산은 검증된 라이브러리로, 월말·윤일을 테스트한다.
- "지금이 언제인지 코드가 안다" → 테스트·재현 불가 → 현재 시각은 주입 가능하게 한다.

## 문자열·인코딩

- "문자 하나 = 바이트 하나 = 화면 폭 하나" → 다국어·이모지·결합 문자 → 길이·자르기·정렬·폭 계산은 정본 함수 하나로(플럼빙과 정합성 정본).
- "같은 글자는 같다" → 대소문자, 유니코드 정규화(NFC/NFD), 앞뒤 공백, 전각·반각 → 비교·키 생성 전에 정규화하는가, 정규화 규칙이 한 곳인가.
- "빈 문자열과 null은 같다(또는 다르다)" → 둘의 의미를 정하고 계약에 적는다. 0·`""`·`false`를 "없음"으로 오인하는 falsy 검사가 없는가.
- "경로·줄바꿈·구분자는 하나다" → OS별 경로 구분자, CRLF/LF, CSV 구분자·따옴표 → 플랫폼 API를 쓰고, 문자열 결합으로 경로·쿼리·명령을 만들지 않는다(교차 품질 정본).

## 동일성·비교

- "같아 보이면 같다" → 참조 vs 값 동일성, 부동소수 오차, 정밀도 차이 → 무엇을 기준으로 같은지(id·값·정규화된 값)를 정하고 그 비교를 한 곳에 둔다. 금액은 decimal(설계 정본).
- "정렬돼 있다" → 입력·맵·집합·이벤트 도착 순서는 보장되지 않는다 → 순서에 의존하면 명시적으로 정렬하고, 안정 정렬 여부와 동점 처리를 정한다.
- "부정의 부정은 읽힌다" → `isNotDisabled`, 이중 부정 플래그 → 긍정형 이름으로 바꾼다(식별자·문구·주석 정본).

## 기본값·상태

- "기본값은 무해하다" → 가변 기본 인자, 공유 인스턴스, 누락된 설정의 조용한 기본값 → 기본값이 호출 간에 공유되지 않는가, 누락은 fail-fast인가(교차 품질 정본).
- "초기 상태는 항상 이 상태다" → 재시작·재개·부분 실패 후 다른 상태에서 시작 → 모든 진입이 현재 상태를 읽고 시작하는가.
- "검증했으면 안전하다" → 검증 결과를 버리고 원본을 계속 씀, 검증과 사용 사이에 값이 바뀜(TOCTOU) → 검증된 값을 이후 경로가 쓰는가.

## 흐름 제어

- "오류 뒤에는 멈춘다" → early return·throw 누락으로 오류 로그만 남기고 다음 줄이 실행 → 오류 분기마다 흐름이 실제로 끝나는지 확인한다. 조기 `return` 하나가 뒤의 계약 검사를 통째로 없애는 반대 경우도 본다.
- "switch는 모든 경우를 다룬다" → enum에 값이 추가됨 → default 분기에서 조용히 넘기지 않고 exhaustiveness를 컴파일러·테스트로 강제한다.
- "비동기 결과는 기다렸다" → await·join 누락, 잃어버린 Promise·task → 결과가 실제로 소비되는가, 예외가 어디로 가는가.

## 단위·형식

- "단위는 자명하다" → ms vs s, bytes vs KB, 퍼센트(0~100) vs 비율(0~1), 도 vs 라디안 → 이름·타입에 단위를 넣고(`timeoutMs`), 경계에서 한 번만 변환한다.
- "식별자는 숫자다" → 큰 정수의 정밀도 손실(JS number), 선행 0, 정렬 순서 → 식별자는 문자열 또는 전용 타입으로.

## 실행 환경

- "실행 중인 코드는 방금 고친 코드다" → 낡은 빌드·이미지·캐시·핫리로드 실패 → 산출물의 버전을 확인하고 나서 판정한다(진단과 디버깅 정본, 교차 품질 정본).
- "로컬에서 되면 어디서나 된다" → 로케일·타임존·권한·경로·의존성 버전 차이 → 환경 동등성을 설정값 차이로만 두고, CI에서 같은 게이트를 돌린다.

## 적용

- 이 카탈로그는 훑는 것으로 끝나지 않는다. 해당 항목마다 깨지는 조건을 테스트로 만들고, 발견한 가정은 사양·계획 정본의 가정 원장에 올린다.
- 저장소·도메인에서 반복 발견된 구멍은 이 목록에 일반화해 추가한다. 프로젝트 고유 사례는 그 저장소의 회귀 테스트가 소유한다.

## 핑계와 반박

| 핑계 | 반박 |
|---|---|
| "사소한 경우라 넘어가도 된다" | 판단 기준은 크기가 아니라 파급이다. 비교 연산자 하나가 저장·화면·테스트 전체에 퍼진다 |
| "그런 입력은 실제로 안 들어온다" | 재시도·중복 클릭·다국어·월말은 반드시 온다. 테스트로 확인한다 |
| "주석으로 가정을 적어 두었다" | 주석은 실행되지 않는다. 가정은 테스트나 타입으로 고정한다 |

## 위험 신호

- 목록의 해당 항목을 확인하지 않은 채 "사소해서" 넘김
- 가정을 테스트 없이 주석으로만 남김
- 같은 구멍이 인접 경로에 남아 있는데 지적된 한 곳만 고침

## 종료 게이트

- [ ] 변경이 닿는 범주(수량·경계·시간·문자열·비교·기본값·흐름·단위·환경)를 훑었다
- [ ] 해당 항목마다 깨지는 조건의 테스트가 있거나, 비해당 근거가 있다
- [ ] 발견한 구멍과 같은 primitive를 쓰는 인접 경로를 검색했다
