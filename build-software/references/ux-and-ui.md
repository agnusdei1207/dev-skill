# UX/UI (위상 2)

이 파일은 사용자에게 닿는 작업의 설계 철학·상태·접근성·반응형·정보 구조 계약을 소유하며, 이 계약은 구현 전에 확정한다. 계약을 먼저 세우면 구현은 계약을 채우는 일이 되고, 빠뜨린 상태를 배선까지 거슬러 다시 뚫는 일이 없어진다. 화면의 품질은 요소를 많이 넣은 정도가 아니라, 사용자가 지금 해야 할 일을 방해하지 않으면서 필요한 정보와 제어만 남긴 정도로 판정한다. 공유 컴포넌트·디자인 토큰·조립식 규율의 정본은 컴포넌트와 재사용 정본이 소유한다.

## 절차

1. 실제 대상·사용자·주 업무에서 시각 방향과 기억점 하나를 확정한다.
2. 화면마다 핵심 과업과 주 행동을 한 문장으로 적는다.
3. 실제 화면을 보고 상시 요소를 `주요 / 보조 / 필요할 때 / 제거`로 분류하고, 템플릿 기본값을 감사한다.
4. 중복 진입점·상시 패널·중첩 컨테이너·반복 문구를 제거하고, 중립 표면에서 위계를 세운다.
5. 공통 토큰·컴포넌트로 모션·상태·아이콘·스크롤을 한 번 정의한다.
6. 상태·접근성·반응형·정보 구조를 배선하고 테스트로 고정한다.
7. 대표 폭·양 테마에서 실제 렌더 전후를 비교한다.

## 설계 철학

시각 방향을 먼저 고른다. 구현 전에 제품의 실제 대상·사용자·이 화면의 주 업무를 한 문장으로 묶고, 그 맥락에서만 나오는 시각 어휘와 기억점 하나를 정한다. 색·타입·간격·레이아웃 원칙을 짧은 토큰 계획으로 만든 뒤 코드에 들어간다. 같은 계획을 이름만 바꿔 전혀 다른 제품에도 붙일 수 있으면 방향을 다시 잡는다. 다른 제품과 디자인 시스템은 결과 화면이 아니라 삭제·위계·상태·조립 원리를 참고한다.

템플릿 기본값을 선택으로 착각하지 않는다. 동일한 둥근 카드의 반복, 모든 제목 위의 장식 라벨, 근거 없는 그라데이션·화살표·모노스페이스 메타, 같은 radius·shadow를 전 계층에 적용하는 것은 관계를 설명할 때만 쓴다. 차별성은 한 곳에 집중하고 주변은 조용하게 유지한다. 이 항목들은 금지 목록이 아니라 맥락 없는 자동 선택을 찾는 감사 기준이다. 이 기준은 [Anthropic Frontend Design](https://github.com/anthropics/claude-plugins-official/blob/main/plugins/frontend-design/skills/frontend-design/SKILL.md)의 의도성·비템플릿 원칙을 내부 개발 규율에 맞게 일반화한다.

한 화면, 한 초점. 화면마다 현재 핵심 과업과 주 행동을 한 문장으로 정한다. 첫 시선은 주 콘텐츠 또는 주 행동으로 간다. 브랜드 장식·상태 배지·보조 탐색이 먼저 경쟁하면 위계 실패다. 보조 행동은 주 행동보다 조용하고, 드문 행동은 필요할 때만 연다.

더하기 전에 덜어낸다. 구현 전 상시 요소를 `주요 / 보조 / 필요할 때 / 제거`로 분류한다.

- 주요: 현재 과업을 직접 수행한다.
- 보조: 현재 판단에 필요하지만 초점을 가져가면 안 된다.
- 필요할 때: 고급 설정, 드문 관리, 파괴적 행동처럼 요청 시 드러난다.
- 제거: 같은 의미의 반복, 장식만 하는 chrome, 설명을 반복하는 배지·문구, 동작 없는 제어.

요소를 뺀 뒤 사용자 여정과 상태 이해가 그대로면 다시 넣지 않는다. 새 요소는 무엇을 가능하게 하고 왜 상시 노출이어야 하는지 답해야 한다. 제거해도 핵심 과업·상태 이해·복구·접근성이 손상되지 않으면 제거한 상태가 정본이다. 반대로 이미 명료하고 일관된 화면·IA는 보존하고 재구성 자체를 목적으로 삼지 않는다.

구조가 장식보다 먼저다. 위계는 레이아웃·정렬·여백·크기·글자 굵기로 먼저 만든다. 색·테두리·그림자·그라데이션으로 구조 부족을 덮지 않는다. 관련 항목은 정렬과 여백으로 묶고 모든 그룹을 카드로 감싸지 않는다. 카드는 독립적으로 선택·이동·비교하는 객체에만 쓴다. 기본 표면은 중립색이고, 강조색은 주 행동·포커스·선택·실제 상태에만 쓴다.

동시에 보이는 표면을 최소화한다. 상시 패널은 동시에 읽거나 조작해야 하는 최소 집합만 남긴다. 세 개 이상의 상시 표면이 경쟁하면 각각의 동시 표시 근거를 적고, 근거 없는 표면은 drawer·popover·접힘·별도 단계로 옮긴다. 같은 대상의 탐색·선택·편집 진입점을 header·sidebar·본문에 복제하지 않는다. 화면이 넓어졌다는 이유로 빈 공간을 기능이나 장식으로 채우지 않는다.

점진적으로 드러낸다. 자주 쓰는 핵심 제어는 숨기지 않는다. 고급 옵션·긴 도움말·드문 관리 기능은 요청하거나 해당 상태가 발생했을 때 보인다. 비활성 제어는 이유와 다음 행동을 짧게 제공하고, 정상 상태에서 실패 안내를 계속 점유시키지 않는다. 빈 화면은 짧은 맥락, 하나의 다음 행동, 필요하면 소수의 예시만 제공한다.

움직임과 상호작용도 하나의 언어다.

- 모션은 상태 전환의 피드백이다. 사용자가 열기·선택·확인·이동한 결과는 무엇이 바뀌었는지 보이게 하고, 사용자가 시작하지 않은 모션과 수동 컨테이너마다 붙는 hover는 주의를 요구하는 근거가 있을 때만 쓴다. 기본 duration `300ms`와 easing·거리·press scale을 제품 공통 토큰으로 정하고, 같은 종류의 열림·닫힘·hover·press에 같은 값을 쓴다. 저장소가 다른 값을 승인했으면 그 토큰을 따른다.
- 열림과 닫힘은 양방향 같은 토큰을 쓰고, 닫힘 애니메이션이 끝나기 전에 DOM을 제거하지 않는다. `prefers-reduced-motion: reduce`에서는 duration을 정확히 `0ms`로 하고 이동·반복 animation을 끈다. `0.01ms` 근삿값이나 JavaScript의 이전 duration 대기를 남기지 않으며, 종료 이벤트가 없어도 close·focus 복원·자원 정리가 즉시 끝나게 lifecycle을 같은 토큰에 연결한다.
- 모든 상호작용 제어는 기본·hover·active/pressed·focus-visible·disabled 상태를 같은 체계로 갖는다. hover만으로 의미나 동작 가능 여부를 전달하지 않는다.
- 익숙한 소형 행동은 아이콘만 쓸 수 있되 접근 가능한 이름, hover/focus 설명, 충분한 터치 영역, 파괴적 행동의 구분을 보존한다. 의미가 모호하거나 고위험 결정을 확인하는 행동은 텍스트 라벨을 유지한다.
- 스크롤바도 인터페이스 일부다. 공통 CSS·테마 토큰으로 절제된 custom scrollbar를 만들되 스크롤 가능성·thumb 대비·hover/drag 상태를 숨기지 않고, 네이티브 키보드·터치 동작을 보존하며 장식용 JavaScript 스크롤을 만들지 않는다.

작업 유형별 적용. 작업 공간·에디터는 주 콘텐츠와 작업 제어를 중심에 두고, 맥락을 바꾸는 표면(프로젝트 목록·이력·설정)의 상시 점유를 먼저 반증한다. 미리보기 도구막대에는 미리보기에 실제 영향을 주는 제어와 연결 상태만 둔다. 입력·AI 대화는 하나의 composer에 텍스트·음성·첨부를 조립하고, 음성 결과는 자동 실행하지 않는 편집 가능한 초안이 된다. 설정·관리 화면은 사용자 목적별로 필드를 묶고 기본 경로를 먼저 읽히게 하며, 저장·검증·write-only 비밀 같은 사실은 장식보다 명확한 라벨로 전달한다.

## 상태 계약

사용자에게 닿는 흐름은 다음 상태를 사실대로 보인다. 실제로 존재하는 상태는 하나도 비우지 않고, 존재하지 않는 상태를 억지로 만들지도 않는다.

| 상태 | 의미 | 미완성 판정 |
|---|---|---|
| loading | 처리 중임을 알림 | 응답 지연 동안 화면이 멈춘 듯 보이면 실패 |
| empty | 데이터 없음을 안내 | 빈 목록이 오류처럼 보이거나 안내 없이 비면 실패 |
| disabled | 지금 할 수 없는 동작 | 왜 못 하는지 신호 없이 눌리기만 하면 실패 |
| success | 성공을 확인 | 성공했는데 변화가 없어 사용자가 반복 시도하면 실패 |
| error | 실패를 사실대로 | 실패를 성공처럼 보이거나 원인·다음 행동이 없으면 실패 |
| retry | 재시도 경로 | 회복 가능한 실패에 재시도 수단이 없으면 실패 |
| cancel | 취소 경로 | 되돌릴 수 있어야 할 진행을 멈출 수 없으면 실패 |
| recovery | 회복 후 상태 복원 | 실패·취소 후 이전 입력·선택이 사라지면 실패 |
| 중복요청 | 같은 요청 재발행 방지 | 두 번 눌러 두 번 실행되거나 경합하면 실패 |

- 무손실 회복이 핵심이다. 실패·취소·재시도 어떤 경로에서도 입력한 값과 선택이 유실·변형되지 않는다. 이것은 UX이자 무손실 배선(플럼빙과 정합성 정본) 요구다.
- 자가 잠금(Self-Bricking) 금지: 설정·수정·복구 화면에서 이전 서버의 에러·비가용 상태(`error`, `loadFailed`, `available === false`, 503 등)를 이유로 사용자의 입력이나 저장/검증 버튼을 비활성화(`disabled`)해 두는 것을 금지한다. 에러 상태일수록 올바른 값을 입력해 시스템을 복구할 수 있는 경로는 상시 열려 있어야 한다. 버튼의 `disabled`는 오직 현재 클라이언트 폼 입력이 유효한지(형식 충족 여부)와 현재 네트워크 저장 요청이 진행 중인지에 의해서만 결정된다.
- 정직한 상태 표시. 실패를 숨기거나 성공처럼 꾸미지 않는다. 낙관적 UI를 쓰면 실패 시 되돌리는 경로를 함께 만든다. "없어야 한다"를 보이는 화면은 "있어야 하는" 짝 화면과 함께 검증한다(QA와 검증 정본의 검사가 실제로 재는지 검증).
- 알림 경로는 하나. 성공·오류·경고의 사건 알림은 공용 toast primitive 한 곳으로 보내고, 같은 사건을 toast와 본문에 중복 노출하지 않는다. 진행·저장 여부처럼 지속되는 상태는 해당 제어의 상태 표현이 소유하고, retry·cancel은 가까이 두되 toast 설명을 반복하지 않는다. 오류 문구는 식별자·문구·주석 정본의 사용자 문구 기준을 따른다.
- placeholder와 실제 상태를 분리한다. placeholder는 빈 입력에 허용되는 값의 예시·형식만 보여 주고, 저장값·기본값·검증 결과·저장 완료를 뜻하지 않으며 접근 가능한 라벨을 대신하지 않는다. 실제 값은 input value로, 저장·검증 상태는 확인된 서버 상태에 따른 짧은 표시로 전달한다. write-only 비밀은 원문을 다시 채우지 않고 masked 저장 상태와 새 값 입력을 구분한다. 라벨·placeholder·도움말이 같은 내용을 반복하면 제거한다.
- 입력 한도는 사람 기준으로 표시한다. 남은 양은 `글자`·`항목`·`분`·파일 수처럼 사용자가 판단하는 단위로 보이고, 전송 바이트가 제품 개념이 아니면 `바이트 남음`을 노출하지 않는다. 화면 글자 수·DOM 입력 제한·정규화·API 계약·영속 상태가 같은 의미와 경계값을 쓰며, 다국어·이모지·결합 문자를 포함해 경계 바로 아래·정확히 경계·바로 위를 테스트한다. 서버는 별도로 UTF-8 바이트 상한과 JSON/파일 framing 상한을 집행하되 그 방어를 UI 카운터에 노출하지 않는다.
- 터미널·TUI 화면 무결성과 날것 I/O 격리: TUI나 Raw mode 환경에서 백그라운드 스레드·워커·프로바이더가 날것의 `stdout`/`stderr`(`println!`, `eprintln!`, `console.log`)를 직접 호출하는 것을 금지한다. 화면 버퍼 바깥의 날것 쓰기는 ANSI 커서 위치를 틀어버리고 줄바꿈(`\r\n`) 불일치로 활성 UI 위젯과 글자가 겹치는 심각한 화면 깨짐(ghosting·staircasing)을 부른다. 모든 상태와 오류는 구조화된 이벤트 버스를 통해서만 전달되고 TUI의 통제된 뷰포트에서만 렌더한다. 내부 한계값(`usize::MAX` 등)이나 원시 JSON 에러 덩어리를 화면에 그대로 노출하지 않고, 사람이 즉시 이해할 수 있는 정제된 문구(핵심 에러 메시지 추출, `unlimited` 등)로 표시한다.
- 계약을 테스트로 고정한다. 상태 집합은 각 상태를 렌더하는 테스트로, 접근 가능한 이름은 그 이름으로 요소를 찾는 테스트로, 무손실 회복은 실패·취소 후 입력 보존 테스트로 잠근다.

## 접근성

영향 범위가 실제로 건드리는 축을 실측한다. 전부를 형식적으로 나열하지 않는다.

- pointer: 마우스·터치로 모든 동작에 닿고, 터치 타깃은 충분히 크다(관례상 44px 이상).
- keyboard: 마우스 없이 모든 동작에 닿고, 탭 순서가 논리적이며 포커스 함정이 없다.
- focus: 포커스 위치가 보이고, 모달 열림·닫힘 후 포커스가 올바른 곳으로 이동·복원된다.
- screen reader: 요소가 겉모습이 아니라 이름으로 읽힌다. 아이콘 버튼은 접근 가능한 이름을 갖고, 로딩·오류 같은 상태 변화가 보조기술에 전달된다.
- reduced motion: 위 모션 항목의 `0ms`·즉시 종료 계약을 CSS computed style과 JavaScript lifecycle 양쪽에서 검증한다.
- interaction states: 위 상호작용 상태 체계가 색 하나에만 의존하지 않는지, 열림·닫힘 양방향과 스크롤 표면을 실제 브라우저에서 확인한다.

요소는 자기가 내건 이름으로 찾게 만든다. 상자·태그·조상 관계로 요소를 식별하면 배치를 한 번 다듬는 것만으로 접근성 배선과 테스트가 조용히 대상을 잃는다. 검사가 부르는 이름과 화면이 다는 이름이 같은 변경에서만 바뀌도록 테스트로 함께 붙든다.

WCAG 2.x AA 준거. 인식 가능(본문 대비 4.5:1, 큰 텍스트 3:1 이상, 색만으로 정보 전달 금지, 대체 텍스트·자막), 운용 가능(모든 기능 키보드 접근, 포커스 함정 없음, 충분한 타깃, 시간 제한·자동 이동 통제), 이해 가능(명확한 라벨·오류 안내, 일관된 내비게이션, 예측 가능한 동작), 견고(시맨틱 마크업과 필요한 곳의 ARIA, div로 버튼을 흉내 내지 않음). 자동 검사(axe 등)는 일부만 잡으므로 키보드·스크린리더로 실제 여정을 밟는다.

테마 동등성. light/dark는 같은 상태·전환 계약의 두 표현이다. 양쪽에서 본문·입력·placeholder·아이콘·toast·dialog·custom scrollbar의 대비와 hover·press·focus·disabled를 같은 기준으로 확인한다. system 선택이 있으면 운영체제 설정 변경에도 실제 테마와 computed color가 함께 바뀌는지 확인한다.

## 반응형

- 반응형은 축소가 아니라 우선순위 재배치다. 좁은 화면에서는 핵심 과업을 먼저 두고 보조 표면을 접거나 다음 순서로 내린다. 데스크톱의 다열을 비율만 줄여 우겨 넣지 않는다.
- 읽기 순서·키보드 포커스 순서가 시각 순서와 일치한다. 모바일에서도 입력·현재 상태·취소·복구 경로는 화면 밖으로 밀려나지 않는다.
- 저장소의 브레이크포인트(예: 360/768/1280/1600px)가 있으면 그 값을 따른다. 상대 단위와 유연한 레이아웃을 쓰고, 넓은 콘텐츠(표·다이어그램·코드)는 자기 컨테이너 안에서 스크롤시켜 본문이 가로로 넘치지 않게 한다.
- 눈으로 확인한다. 시각 변경은 빌드 성공이 아니라 실제 렌더로 판정한다. 대표 폭에서 전후를 비교해 첫 초점, 잘림, 정렬, 대비, 빈 공간, 포커스 순서, 상태 노이즈, 열림·닫힘·hover·press를 본다. 차트·표는 머리글·축·범례·주석이 잘리지 않고 열 수가 맞아 표로 렌더링되는지 확인한다. 도구가 없으면 무엇을 확인하지 못했는지 정직하게 남긴다.

## 정보 구조

사용자가 무엇이 어디 있는지 알고, 찾고, 길을 잃지 않는가를 다룬다. 코드 폴더 구조와 다르다. 화면·콘텐츠·여러 개체가 있는 작업에서 구현 전에 확정한다.

- 콘텐츠·도메인 모델: 제품에 존재하는 개체와 관계, 무엇이 최상위이고 무엇에 속하며 목록·상세·생성·편집의 단위가 무엇인지 먼저 정한다. 개체·필드 이름은 용어집의 사용자 어휘로 짓고, 내부 DB 용어를 화면에 노출하지 않는다. IA는 사용자의 멘탈 모델을 따르지 내부 저장 구조를 따르지 않는다.
- 분류·라벨링: 항목을 사용자가 기대하는 방식으로 묶고, 범주·라벨은 바로 이해하는 말로 쓴다. 엄격 분류인지 태그·패싯인지 정하고, 억지 단일 분류로 못 찾게 만들지 않는다. 라벨은 제품 전체에서 일관된다.
- 내비게이션: 1차·2차·유틸리티 계층을 정하고 깊이와 너비의 균형을 잡는다. 사용자는 항상 여기가 어디인가·어디로 갈 수 있는가·어떻게 돌아가는가에 답할 수 있어야 한다(현재 위치 표시·breadcrumb·되돌아가는 경로). 자주 쓰는 것은 얕게, 드문 것은 깊게 둔다.
- 라우팅·딥링크: 주소는 안정적이고 의미 있게 짓는다. 상태가 담긴 화면(상세·필터·탭)은 딥링크·북마크·공유가 가능하고 새로고침해도 복원된다. 뒤로 가기가 기대대로 동작하며 모달·탭·필터가 히스토리와 어긋나지 않는다. 라우트 변경 시 옛 링크의 리다이렉트·안내를 정해 죽은 링크를 남기지 않는다.
- 발견성: 탐색·검색·필터 중 콘텐츠에 맞는 수단을 고른다. 양이 많으면 검색·필터를, 구조가 뚜렷하면 탐색을 우선한다. 검색·필터의 빈 결과·로딩·오류 상태를 사실대로 다루고 다음 행동을 제시한다.
- 정보 밀도: 한 화면에 필요한 만큼만 보이고 요약에서 상세로 점진적으로 공개한다. 과잉은 압도, 과소는 왕복을 부른다.

현지화·형식(해당 시). 날짜·시각·숫자·통화·단위는 로케일 형식으로 표시하고 저장은 표준 형식(타임존 포함 시각, ISO 8601, 통화 코드)으로 한다. 문구 팽창·축소를 고려해 고정 폭에 박지 않고, 대표 언어로 렌더를 확인하며, 어순이 다르므로 문장을 조각으로 잇지 않는다. 다국어·이모지·결합 문자에서 길이 계산·자르기·정렬이 깨지지 않게 하고, RTL이 대상이면 레이아웃 방향을 검증한다. 현지화가 저장소 범위가 아니면 형식적으로 다루지 않되 시각·통화의 저장 형식은 항상 지킨다.

## 핑계와 반박

| 핑계 | 반박 |
|---|---|
| "해피 패스부터 만들고 상태는 나중에" | 빠진 상태는 배선까지 거슬러 다시 뚫어야 한다. 상태 계약을 먼저 세운다 |
| "중요하니 카드·배지·색으로 강조하자" | 모든 것을 강조하면 아무것도 강조되지 않는다. 위계는 배치·여백·크기로 먼저 만든다 |
| "미니멀하게 라벨을 빼자" | 라벨·상태·취소·포커스 표시는 장식이 아니다. 제거하면 과업과 접근성이 손상된다 |
| "빌드가 되니 화면도 괜찮다" | 시각 변경은 실제 렌더로 판정한다. 대표 폭·양 테마에서 눈으로 확인한다 |
| "에러 상태면 저장 버튼을 막자" | 자가 잠금이다. 에러일수록 복구 경로는 열려 있어야 한다 |
| "다크 모드는 색만 반전하면 된다" | 대비·상태·포커스를 양쪽에서 같은 기준으로 확인하지 않으면 한쪽이 깨진다 |

## 위험 신호

- 제품 맥락 없이 유행 스타일을 고르거나 다른 제품에도 그대로 붙는 시각 계획, 다른 제품의 시각 결과만 복제
- 정보 구조는 그대로 두고 색과 radius만 바꾸는 skin-only 정리, 기능마다 카드·배지·색을 더해 중요도 표현
- 동시 표시 근거 없는 세 개 이상의 상시 패널, 같은 행동의 반복 진입점, 정상 상태에서 상시 노출되는 도움말·오류 가능성·설정 안내
- 미니멀리즘을 이유로 라벨·상태·취소·복구·포커스 표시 제거, 아이콘만 남기며 이름·설명·터치 영역 제거
- 화면마다 다른 duration·easing 또는 닫힘을 잘라 버린 모션, 상태 변화가 없는 hover, 수동 표면마다 반복되는 장식 motion, 방치되거나 완전히 숨긴 스크롤바
- 빈 상태 집합 항목, 실패·취소 후 입력 유실, 겉모습으로 요소 식별, 한 테마만 검증
- 고아 콘텐츠, 되돌아갈 길 없는 막다른 화면, 딥링크·복원 불가 상태, 내부 DB 구조를 그대로 옮긴 조직, 빈 결과 방치

## 종료 게이트

- [ ] 화면마다 핵심 과업·주 행동 한 문장과 상시 요소 분류가 있고, 근거 없는 상시 표면이 없다
- [ ] 실제로 존재하는 상태가 모두 렌더되고, 실패·취소 후 입력이 보존됨을 테스트로 확인했다
- [ ] 영향받는 접근성 축(keyboard·focus·screen reader·reduced motion·pointer)을 실측했다
- [ ] 대표 폭과 양 테마의 실제 렌더 전후 비교를 했다(도구가 없으면 확인하지 못한 것을 명시)
- [ ] 화면·개체가 있으면 정보 구조(위치·되돌아가기·딥링크·빈 결과)가 정해졌다
