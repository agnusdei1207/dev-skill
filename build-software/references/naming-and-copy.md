# 식별자·문구·주석

이 파일은 코드 안의 이름, 사용자에게 보이는 문구, 주석을 소유한다. 도메인 개념의 단어 선택은 도메인 모델링 정본의 용어집이, 폴더·파일 이름은 코드 조직 정본이 소유한다.

## 식별자

- 이름은 의도를 드러낸다. `data`·`tmp`·`handle2`·`doStuff` 금지. 함수는 동사구, 변수·타입은 명사구, boolean은 `is/has/should/can`. 언어별 케이싱 관례를 따르고, 약어는 표준(`id`·`url`)일 때만.
- 거짓말하는 이름 금지. `getUser`가 생성하거나, `list`가 하나만 돌려주거나, `isValid`가 부작용을 내면 실패다.
- 긍정형으로 짓는다. `isNotDisabled` 같은 이중 부정 대신 `isEnabled`.
- 단위를 이름에 넣는다. `timeout` 대신 `timeoutMs`, `size` 대신 `sizeBytes`. 단위 타입이 있으면 타입으로.
- 수는 카디널리티 계약이다. 여럿일 수 있으면 복수(`recipients`·`owners`), 정확히 하나면 단수. "지금은 하나"는 단수의 근거가 아니다. 수신자·구독자·대상·소유자·세션·기기·테넌트·역할·결과처럼 도메인상 여럿이 가능한 개념은 처음부터 집합으로 이름 짓고 모델링한다. 0..1 / 1 / 0..N / 1..N 중 무엇인지 이름·타입·검증이 함께 말한다.

## 사용자 문구

- 도메인 지식 없이 첫 줄에서 뜻이 읽히고(`null`·`payload` 노출 금지), 군더더기 없이 짧고, 기계 번역투가 아니며, 제품 전체에서 어조·용어·문장부호가 일관되고, 실제 상태를 사실대로 말한다.
- 에러는 무엇이 왜 잘못됐고 무엇을 할 수 있는지를 말한다.
- 0개·1개·여러 개의 문구와 복수형 규칙을 사실대로 다룬다. 현지화가 있으면 문구를 코드에 박지 않는다.

## 주석

- 주석은 "왜"만. 코드가 말하는 "무엇"을 반복하지 않는다. 비자명한 결정·제약·우회의 이유, 외부 사양 참조를 적고 인텐트 번호를 단다.
- 낡은 주석은 거짓말이므로 코드와 같은 변경에서 맞추거나 지운다. 주석 처리한 옛 코드·이유 없는 `TODO`를 남기지 않는다.

## 핑계와 반박

| 핑계 | 반박 |
|---|---|
| "지금은 수신자가 하나뿐이다" | 단수 이름·단일 필드가 여럿을 만나면 첫 원소만 살아남고, 나중 변경은 계약을 깨는 이관이다 |
| "이름은 대충 짓고 주석으로 설명하자" | 주석은 낡고 이름은 호출부마다 읽힌다. 정직한 이름이 안 나오면 설계가 흐린 것이다 |
| "에러 메시지는 개발자만 본다" | 사용자에게 닿는 순간 원인과 다음 행동이 없는 문구는 문의와 재시도를 만든다 |

## 위험 신호

- 의미 없는 이름, 거짓말하는 이름, 이중 부정 boolean, 단위 없는 시간·크기 이름
- 집합을 단수로 명명, 단일 필드에 여럿을 담음
- 내부 용어·예외 문자열이 노출된 사용자 문구, 화면마다 다른 어조·용어
- "무엇"을 반복하는 주석, 낡은 주석, 주석 처리한 코드, 이유 없는 `TODO`

## 종료 게이트

- [ ] 새 식별자의 수(단수·복수)가 도메인 카디널리티와 일치하고, 시간·크기 이름에 단위가 있다
- [ ] 사용자 문구가 상태를 사실대로 말하고, 에러는 원인과 다음 행동을 담는다
- [ ] 바뀐 코드 주변의 주석이 코드와 일치하고, 주석 처리 코드·이유 없는 `TODO`가 없다
